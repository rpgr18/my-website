dsa-cli

Type
Open source, MIT
Timeline
Aug 2026
Stack
Python · Click · Rich · SQLite · pytest
Outcome
All 150 NeetCode problems with 968 test cases, graded Big-O and spaced repetition, with two dependencies.

Grinding problems in a browser tab teaches you to pass a judge. dsa-cli is meant to teach the pattern, then make you prove you still know it three weeks later. No browser, no login, no network.

The loop

dsa roadmap          # 18 categories in study order
dsa start two-sum    # writes a stub and opens $EDITOR
dsa run two-sum      # sample tests, with a diff for each failure
dsa hint two-sum     # one hint at a time
dsa submit two-sum   # full suite, then the complexity quiz
dsa review           # what spaced repetition says is due

Every problem ships with a statement, a typed stub, 4–9 test cases, a commented reference solution, target complexities and three escalating hints. That’s 968 cases in total, including empty inputs and hidden performance cases that separate an accepted solution from a lucky one.

Grading what interviews test

After a solution passes, you state its time and space complexity and it gets graded. The parser accepts the many ways people write the same bound (O(n log n), n*logn, linearithmic) while still telling O(n) from O(n²). Then you grade how it felt, and SM-2 schedules the next review: a problem you barely solved comes back tomorrow, one you nailed comes back in two weeks.

Two design decisions

Solutions run in a child process, on a big-stack thread with a per-case timeout, so an infinite loop or a blown recursion limit becomes a TIMEOUT row instead of crashing the CLI. And comparison is pluggable, because many problems have more than one right answer: Course Schedule II accepts any valid topological order, and Clone Graph checks that the nodes you returned are real copies.

How it’s tested

977 tests with pytest, plus dsa selftest, which runs every reference solution against its own test suite. CI runs both on Python 3.10 through 3.13 on every push.

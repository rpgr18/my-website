SurfPy API

Type
Personal project
Timeline
Nov 2024
Stack
Python · Flask · surfpy · flask-cors
Outcome
Wave forecasts, nearby buoys and tide predictions for any coordinate, from one API.

Checking the surf means stitching together NOAA services that each speak a different format: wave-model forecasts published as GRIB files, buoy feeds from the National Data Buoy Center, and tide predictions from NOAA Tides & Currents. SurfPy API wraps the open-source surfpy library in a small Flask service, so a client asks one question, what the water is doing at this latitude and longitude, and gets JSON back.

Three blueprints

Each data source is its own Flask blueprint, all registered on one app with CORS enabled so a browser front end can call it directly.

BlueprintWhat it returns
ForecastWave height, period and direction for the next few days, split into swell components, plus wind. It can also return a buoy’s latest detailed readings.
BuoysThe closest NDBC stations to a point with their distance, filterable by count (1–10), active status and buoy type, and each station’s recent readings.
TidesThe nearest NOAA tide station, its high and low tides and the full prediction curve for 1 to 10 days.

Picking the right wave model

NOAA runs separate regional GFS wave models. The forecast route checks whether a point falls inside the US West Coast model’s box (25–50° N, 110–150° W) and uses it there, falling back to the Atlantic model everywhere else.

Tides that don’t come back empty

Not every tide station publishes every vertical datum, so asking for one blindly can return nothing. The tide route tries mean lower low water first, then mean sea level, then mean tide level, and reports which datum it used alongside the station it picked and how far away it is.

Caching and errors

Buoy lookups are memoized with an in-process LRU cache, so repeat requests for the same station don’t go back to NOAA. Coordinates and query parameters are validated up front, and failures come back as structured JSON, with the valid ranges when the input was the problem, rather than as a stack trace.
